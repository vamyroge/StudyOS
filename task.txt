Bạn hãy triển khai tính năng **Student Context / Learning Memory** cho StudyOS.

MỤC TIÊU:
AI Tutor phải có khả năng đọc và sử dụng dữ liệu học tập thực tế của USER hiện tại từ database để trả lời và tư vấn cá nhân hóa. Không được hard-code dữ liệu và không được lấy dữ liệu của user khác.

Hãy tự inspect toàn bộ repository, database schema, Supabase queries, AI orchestrator, API routes và các feature hiện có trước khi sửa code.

## 1. DỮ LIỆU AI PHẢI ĐỌC ĐƯỢC

Với mỗi authenticated user, xây dựng một `StudentContext` từ database, ưu tiên các dữ liệu thực tế đang tồn tại:

* Profile:

  * tên
  * lớp
  * trường
  * mục tiêu học tập
  * môn học
  * sở thích / ghi chú nếu có

* Learning progress:

  * điểm số
  * mastery
  * tiến độ từng môn
  * tiến độ từng topic/chapter
  * accuracy
  * số câu đúng/sai
  * số lần làm bài
  * lịch sử attempts

* Quiz:

  * các quiz đã làm
  * câu hỏi đã trả lời
  * đáp án user chọn
  * đáp án đúng
  * điểm
  * thời gian làm
  * topic/môn học
  * lỗi thường gặp

* Conversation:

  * lịch sử hội thoại học tập liên quan
  * câu hỏi trước đây
  * câu trả lời
  * topic đã hỏi
  * các vấn đề user thường xuyên hỏi

* Knowledge / learning activity:

  * tài liệu user đã học
  * topic đã xem
  * tài liệu đã lưu nếu schema hỗ trợ
  * lịch sử hoạt động học tập

* Learning analytics:

  * môn mạnh/yếu dựa trên DATA thực tế
  * topic yếu
  * lỗi lặp lại
  * xu hướng tiến bộ
  * các recommendation đã được tạo nếu có

Chỉ sử dụng những field/table thực sự tồn tại trong database. Nếu một loại dữ liệu chưa tồn tại thì không tự tạo dữ liệu giả.

## 2. KIẾN TRÚC

Tạo một service/server-side layer kiểu:

`buildStudentContext(userId)`

Service này chịu trách nhiệm lấy dữ liệu từ Supabase và tạo context chuẩn cho AI.

Ví dụ cấu trúc:

```ts
type StudentContext = {
  profile: ...
  academicProgress: ...
  quizHistory: ...
  conversationHistory: ...
  learningActivity: ...
  weaknesses: ...
  strengths: ...
  recentActivity: ...
}
```

Không đưa toàn bộ database raw vào prompt.

Hãy:

* query đúng user_id
* giới hạn dữ liệu lịch sử hợp lý
* ưu tiên dữ liệu gần đây
* aggregate dữ liệu khi cần
* loại bỏ dữ liệu không liên quan
* tránh prompt quá lớn

## 3. SECURITY — BẮT BUỘC

Đây là phần rất quan trọng.

AI chỉ được đọc dữ liệu của authenticated user hiện tại.

Không bao giờ cho phép:

```text
user A → đọc dữ liệu user B
```

Không tin `userId` do frontend gửi lên.

Lấy user identity từ authenticated Supabase session/server context.

Kiểm tra Row Level Security và authorization.

Mọi query learning data phải được scoped theo authenticated user.

Không expose:

* password
* auth secrets
* API keys
* session tokens
* dữ liệu riêng tư không cần thiết
* dữ liệu của user khác

## 4. TÍCH HỢP AI ORCHESTRATOR

Tìm AI orchestration hiện tại của StudyOS.

StudentContext phải được đưa vào pipeline trước khi gọi LLM:

```text
User Request
    ↓
Authentication
    ↓
Intent Detection
    ↓
Build StudentContext
    ↓
Retrieve Relevant Knowledge
    ↓
AI Prompt
    ↓
LLM
    ↓
Guardrails
    ↓
Response
```

AI phải có khả năng hiểu các câu như:

* "Em đang yếu phần nào?"
* "Hôm nay em nên học gì?"
* "Tại sao điểm Hóa của em thấp?"
* "Dựa vào lịch sử làm quiz của em, hãy tạo 10 câu ôn tập."
* "Em thường sai dạng bài nào?"
* "So với tuần trước em tiến bộ không?"
* "Hãy giúp em lập kế hoạch học."
* "Những kiến thức nào em cần ôn lại?"

Các câu trả lời phải dựa trên database thực tế.

## 5. CONTEXT RELEVANCE

Không phải request nào cũng cần toàn bộ StudentContext.

Thiết kế context selection:

Ví dụ:

Question về quiz
→ quiz history + mistakes + mastery liên quan

Question về kế hoạch học
→ progress + weaknesses + recent activity + goals

Question thông thường về kiến thức
→ knowledge retrieval + chỉ một phần StudentContext cần thiết

Question về lịch sử học tập
→ learning analytics + attempts + conversations

Mục tiêu là giảm token nhưng vẫn đủ context.

## 6. CONVERSATION MEMORY

Khi user hỏi tiếp:

"vậy phần đó em nên ôn thế nào?"

AI phải hiểu "phần đó" dựa trên conversation hiện tại.

Đồng thời có thể sử dụng lịch sử hội thoại trước đó khi phù hợp.

Không gửi toàn bộ lịch sử chat vô hạn vào prompt.

Implement:

* recent messages
* relevant conversation retrieval nếu hệ thống đã có vector/search
* summarization nếu cần

## 7. QUIZ → LEARNING PROFILE

Khi user hoàn thành quiz:

```text
Quiz Result
    ↓
Save attempt
    ↓
Update mastery
    ↓
Update learning analytics
    ↓
StudentContext phản ánh dữ liệu mới
```

AI không được tự đoán điểm hoặc mastery.

Ví dụ database nói:

```text
Hóa
Acid-base: 4/10
pH: 8/10
```

AI phải hiểu rằng Acid-base đang yếu hơn pH.

## 8. DASHBOARD VÀ AI PHẢI DÙNG CÙNG NGUỒN DATA

Không được để:

```text
Dashboard → database
AI → dữ liệu hard-code khác
```

Mà phải:

```text
                 ┌→ Dashboard
Database ────────┤
                 └→ StudentContext → AI
```

Đảm bảo số liệu AI nói ra khớp với số liệu dashboard/database.

## 10. DEBUG / TEST

Tạo test cho:

1. User A chỉ đọc được data A.
2. User B chỉ đọc được data B.
3. User chưa có learning data vẫn chat được.
4. Quiz mới hoàn thành → StudentContext cập nhật.
5. AI trả lời dựa trên quiz history.
6. AI nhận diện weakness từ dữ liệu.
7. Không leak dữ liệu user khác.
8. Không đưa secret/private auth data vào LLM.
9. Dashboard và AI dùng cùng số liệu.
10. Empty/null database không làm AI crash.

Nếu project chưa có test framework, hãy setup test phù hợp với stack hiện tại.
