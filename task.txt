Phát triển một hệ thống học tập hoàn chỉnh cho StudyOS gồm:

1. LƯU LỊCH SỬ HỘI THOẠI

* Mỗi cuộc trò chuyện AI của user phải được lưu vào database.
* Một conversation có:

  * id
  * user_id
  * title
  * subject
  * created_at
  * updated_at
  * messages
* Mỗi message lưu:

  * role: user / assistant
  * content
  * timestamp
  * metadata nếu cần.
* Tự động tạo title ngắn từ câu hỏi đầu tiên nếu user chưa đặt tên.
* Sidebar/page lịch sử hiển thị các cuộc trò chuyện gần đây.
* Cho phép:

  * mở lại conversation
  * tiếp tục chat
  * đổi tên
  * xóa
  * tìm kiếm
  * lọc theo môn.
* User chỉ được truy cập conversation của chính mình.
* Thiết kế RLS đúng với Supabase.

2. TRANG QUIZ ÔN TẬP

Tạo page `/quiz` hoặc route phù hợp với architecture hiện tại.

Có 2 chế độ:

A. Quiz từ lịch sử học tập

AI phân tích:

* các câu hỏi user từng hỏi
* subject
* topic
* kiến thức đã học
* lỗi sai nếu có
* mức độ khó
* lịch sử quiz trước đó

Sau đó tạo quiz cá nhân hóa.

Ví dụ:
User hỏi nhiều về đạo hàm → quiz ưu tiên đạo hàm.
User thường sai Hóa hữu cơ → tăng câu hỏi phần đó.

B. Quick Assessment

Tạo bài test nhanh để đánh giá trình độ hiện tại gồm:

* Toán
* Vật lý
* Hóa học
* Tiếng Anh

Cho phép:

* chọn môn
* số câu: 10 / 20 / 30
* mức độ: cơ bản / trung bình / nâng cao hoặc adaptive
* bắt đầu test.

3. QUIZ ENGINE

Mỗi câu hỏi có:

* question
* options
* correct_answer
* explanation
* subject
* topic
* difficulty
* source
* metadata.

Trong lúc làm:

* timer nếu cần
* progress indicator
* chọn đáp án
* next/previous
* không mất dữ liệu khi reload nếu có thể.

Khi submit:

* chấm điểm
* tính accuracy
* thời gian
* số câu đúng/sai
* topic đúng/sai
* difficulty performance.

Không để AI tự quyết định điểm số ở frontend.
Frontend gửi kết quả lên backend và server/database xác thực dữ liệu.

4. ĐÁNH GIÁ TRÌNH ĐỘ

Sau mỗi assessment, tính:

* score
* accuracy
* estimated mastery
* strengths
* weaknesses
* topics needing review.

Lưu kết quả theo từng môn.

Ví dụ database:

assessment_attempts

* id
* user_id
* subject
* score
* accuracy
* total_questions
* correct_answers
* duration
* created_at

assessment_answers

* attempt_id
* question_id
* selected_answer
* correct
* time_spent

topic_mastery

* user_id
* subject
* topic
* mastery_score
* confidence
* questions_attempted
* questions_correct
* last_attempt_at

Nếu project đã có bảng mastery/learning thì TÍCH HỢP vào schema hiện tại thay vì tạo bảng trùng lặp.

5. ADAPTIVE LEARNING

Không chỉ lưu điểm.

Sau mỗi quiz:

* cập nhật mastery theo subject/topic.
* phát hiện topic yếu.
* đề xuất nội dung cần học lại.
* quiz tiếp theo có thể ưu tiên topic yếu.
* nếu user tiến bộ thì tăng difficulty.
* nếu user liên tục sai thì giảm difficulty và đề xuất ôn lý thuyết.

Ưu tiên thuật toán deterministic/rõ ràng trước; AI chỉ hỗ trợ tạo câu hỏi, giải thích và recommendation khi phù hợp.

6. DASHBOARD

Nâng cấp Dashboard hiện tại để hiển thị dữ liệu thực từ database.

Các section:

OVERVIEW

* Tổng số câu đã làm
* Accuracy
* Quiz đã hoàn thành
* Số giờ học nếu dữ liệu đủ tin cậy
* Chuỗi ngày học nếu đã có tracking.

SUBJECT PERFORMANCE
Hiển thị:

* Toán
* Lý
* Hóa
* Anh

Mỗi môn có:

* mastery/level
* accuracy
* số câu đã làm
* xu hướng tiến bộ.

TOPICS
Hiển thị:

* topic mạnh
* topic yếu
* topic cần ôn.

RECENT ACTIVITY

* conversation gần nhất
* quiz gần nhất
* assessment gần nhất.

RECOMMENDATION
Ví dụ:
"Bạn nên ôn lại đạo hàm trước khi làm quiz nâng cao."
"Bạn đang yếu phần phản ứng oxi hóa-khử."

Tất cả số liệu Dashboard phải lấy từ database thật, KHÔNG hard-code/mock data.

7. DATABASE

Trước khi tạo migration mới:

* đọc toàn bộ schema/migrations hiện tại.
* kiểm tra các bảng conversations, questions, learning, attempts, mastery đã tồn tại chưa.
* tái sử dụng schema hiện có nếu phù hợp.
* chỉ tạo migration mới cho phần còn thiếu.
* đảm bảo foreign key, indexes và RLS.

Thiết kế để user A hoàn toàn không thể đọc dữ liệu học tập của user B.

8. AI QUIZ GENERATION

Tạo một service riêng cho quiz generation.

Input:

* subject
* topics
* difficulty
* number_of_questions
* user_learning_context

Output phải có schema JSON ổn định, ví dụ:

{
"questions": [
{
"question": "...",
"options": ["A", "B", "C", "D"],
"correctAnswer": 0,
"explanation": "...",
"subject": "math",
"topic": "...",
"difficulty": "medium"
}
]
}

Validate output bằng schema trước khi lưu database.

Nếu AI trả JSON lỗi:

* retry có giới hạn
* repair nếu an toàn
* không crash UI.

10. UI/UX

Giữ design system hiện tại của StudyOS nhưng làm UX hiện đại, sạch và giống một AI-native learning platform.

Quiz cần:

* responsive
* keyboard friendly
* loading state
* skeleton
* empty state
* error state
* submit confirmation
* result screen đẹp.

Dashboard phải ưu tiên thông tin quan trọng, tránh nhồi quá nhiều chart.

11. PERFORMANCE

* Không fetch toàn bộ conversation history khi mở Dashboard.
* Dùng pagination cho conversations.
* Dùng server-side aggregation/database query cho statistics.
* Index các cột thường query: user_id, subject, created_at, topic.
* Tránh N+1 queries.
* Không gửi toàn bộ lịch sử chat vào LLM nếu không cần.
* Chỉ lấy learning context liên quan để tạo quiz.

12. TESTING

Viết test cho:

* tạo conversation
* lưu message
* load conversation
* RLS
* tạo quiz
* submit quiz
* chấm điểm
* lưu assessment
* cập nhật mastery
* dashboard statistics
* user isolation
* AI JSON validation.

Test ít nhất với 2 user để đảm bảo dữ liệu không bị cross-user.

13. DEFINITION OF DONE

Tính năng chỉ được coi là hoàn thành khi:

* User chat → conversation tự động được lưu.
* Reload trang vẫn thấy lịch sử.
* Có thể mở lại conversation.
* Có page Quiz.
* Có Quick Assessment cho Toán/Lý/Hóa/Anh.
* Quiz được chấm và lưu database.
* Kết quả cập nhật mastery.
* Dashboard hiển thị dữ liệu thật.
* Topic yếu được phát hiện.
* Quiz sau có thể dựa trên lịch sử học tập.
* RLS bảo vệ dữ liệu.
* Không còn mock data ở các chức năng trên.
* Typecheck/build/test đều pass.

Trước khi code, hãy audit architecture/schema hiện tại và tận dụng tối đa những gì StudyOS đã có. Không rewrite toàn bộ project nếu không cần thiết. Sau khi hoàn thành hãy báo cáo:

1. files đã thay đổi
2. migrations đã thêm
3. database tables đã sử dụng
4. API/server actions mới
5. UI pages/components mới
6. tests đã chạy
7. các phần còn thiếu hoặc cần cấu hình environment.
